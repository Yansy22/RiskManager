# 🛡️ RiskManager: AI Portfolio Guardian Roadmap

## Phase 1: 데이터 정비 및 기초 체력 다지기 (Data Ingestion)
- [ ] **portfolio.json 구조 고도화**
    - 기존 종목 정보에 `score`(1~10점), `confidence`(1~10점) 필드 추가
    - 현금 자산을 하나의 종목처럼 취급하여 비중 계산에 포함
- [ ] **데이터 소스 확장 (data_provider.py)**
    - 과거 수정 종가 데이터: 최근 1~2년치 일일 수익률 데이터 수집
    - 시가총액 데이터: 종목별 시가총액 수집 (시장 균형 비중 계산용)
    - 무위험 수익률: 현재 예금 금리나 단기 국채 금리 데이터 설정

## Phase 2: 동적 리스크 클러스터링 (Dynamic Risk Clustering)
- [ ] **상관계수 행렬(Correlation Matrix) 산출**
    - 모든 종목 쌍 간의 수익률 상관관계 계산
- [ ] **계층적 클러스터링(Hierarchical Clustering) 구현**
    - 상관계수를 거리(Distance)로 변환 ($d = \sqrt{2(1-\rho)}$)
    - Scipy를 사용하여 통계적 유사 그룹(리스크 그룹) 생성
- [ ] **외톨이 종목(Outlier) 처리**
    - 리스크 분산 효과 극대화를 위한 독자 종목 식별

## Phase 3: 블랙-리터만 기대수익률 엔진 (Black-Litterman Engine)
- [ ] **시장 균형 수익률($\Pi$) 역산**
    - 시가총액 비중과 과거 변동성을 기반으로 도출
- [ ] **사용자 견해(View) 수치화**
    - `score` -> 초과 수익률($Q$), `confidence` -> 오차 분산($\Omega$) 변환
- [ ] **베이지안 업데이트 실행**
    - 시장 수익률($\Pi$)과 사용자 견해($Q$)를 결합한 수정 기대수익률 산출

## Phase 4: 제약 조건 기반 포트폴리오 최적화 (Constrained Optimization)
- [ ] **목적 함수 설정**
    - 샤프 지수(Sharpe Ratio) 극대화 지점 탐색
- [ ] **클러스터별 비중 제한(Weight Constraints) 적용**
    - 특정 리스크 그룹 합계 비중 제한 (예: 30% 이하)
- [ ] **최종 최적 비중($w^*$) 산출**
    - 이차 계획법(Quadratic Programming)을 통한 종목별 비중 확정

## Phase 5: 몬테카를로 스트레스 테스트 (Monte Carlo Simulation)
- [ ] **미래 경로 생성**
    - Phase 3의 수익률과 Phase 2의 상관관계를 모수로 1만 개 시나리오 생성
- [ ] **리스크 지표 계산**
    - MDD (최대 낙폭) 및 VaR (Value at Risk) 산출

## Phase 6: AI 인사이트 및 리밸런싱 리포트 (Final Report)
- [ ] **데이터 전송 및 LLM 분석**
    - 현재 vs 최적 비중 및 리스크 지표를 Gemini API로 전송
- [ ] **리밸런싱 가이드 생성**
    - 구체적인 매수/매도 제안 및 실행 가이드 출력
- [ ] **의사결정 및 실행**
    - 매주 월요일 리포트 기반 포트폴리오 수정

## 💡 프로젝트 회고 및 잠정 종료 (Retrospective & Project Closure)

본 `RiskManager` 프로젝트는 포트폴리오 관리 이론을 실제 코드로 구현하며 다양한 기술적 시도를 해본 의미 있는 작업이었습니다. 하지만 포트폴리오 관리에 대해 깊이 공부한 결과, **"잦은 리밸런싱이나 복잡한 동적 비중 조절이 실제 투자 성과나 리스크 관리에 필수적이지 않다"**는 투자 철학적 결론을 내리게 되어 현재 시점에서 프로젝트를 잠정 종료(Sunset)하기로 결정했습니다. 

비록 프로젝트는 여기서 멈추지만, 개발적인 측면에서 다음과 같은 소중한 배움을 얻을 수 있었습니다.

### 1. LangGraph를 활용한 상태 기반 워크플로우 설계
- `StateGraph`와 `TypedDict`를 도입하여 복잡한 데이터 분석 파이프라인(데이터 수집 ➔ 리스크 클러스터링 ➔ 마크다운 리포트 생성 ➔ PDF 빌드)을 노드(Node) 단위로 모듈화했습니다.
- AI/데이터 처리 로직이 얽히지 않도록, 각 단계의 결과물이 명확한 상태(State) 객체를 통해 다음 단계로 안전하고 예측 가능하게 전달되는 아키텍처를 구현했습니다.

### 2. 금융/통계 데이터 다루기 및 알고리즘 직접 구현
- `yfinance` API를 활용해 시계열 가격 데이터를 파싱하고, `pandas`와 `numpy`를 통해 일별 로그 수익률 및 연환산 변동성(Volatility)을 계산하는 방법을 익혔습니다.
- 자산 간 상관계수(Correlation)를 거리(Distance)로 변환($d = \sqrt{2(1-\rho)}$)하고, `scipy`의 계층적 클러스터링(Hierarchical Clustering)을 통해 수학적으로 리스크 그룹을 묶어내는 로직을 직접 구현해 본 것은 큰 성과였습니다.

### 3. 데이터 시각화 및 자동화 리포팅 체계 구축
- `matplotlib`을 이용해 덴드로그램(Dendrogram)과 같은 복잡한 통계적 그래프를 프로그래밍 방식으로 그리고 이미지 파일로 저장하는 방법을 배웠습니다.
- 백엔드에서 산출된 분석 결과를 사람이 읽기 좋은 형태의 Markdown으로 동적 생성하고, 이를 다시 PDF 전략 보고서 형식으로 자동 빌드(`pdf_generator.py`)하는 엔드투엔드 파이프라인을 구축했습니다.

### 4. 도메인 지식과 소프트웨어 요구사항의 본질
- 기술적으로 아무리 정교하고 멋진 시스템(상관관계 트리, 동적 리스크 배분 등)을 설계했더라도, **도메인 지식(투자 철학)의 방향성과 맞지 않으면 결국 불필요한 오버엔지니어링이 된다**는 깨달음을 얻었습니다. 코드를 짜기 전에 '이 시스템이 정말 필요한가'에 대해 본질적으로 고민하고 검증하는 과정이 중요하다는 좋은 레슨런(Lesson Learned)을 남겼습니다.
